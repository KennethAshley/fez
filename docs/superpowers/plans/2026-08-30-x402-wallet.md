# x402 in the Wallet Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** fez agents can pay x402 (HTTP-402/USDC-on-Base) services from their own wallet allowance, gated by the wallet's existing consent/caps, on Base Sepolia.

**Architecture:** Everything lands in the existing `packages/fez-wallet` extension under its allowance model. The money tree grows a standard BIP44 EVM branch (per-persona index). A new `x402.ts` module does the 402 dance via Coinbase's `@x402` SDK with a restricted signer (signs only `TransferWithAuthorization` for the pinned USDC contract). A new agent tool `x402_fetch` wires it behind the existing ✅-consent flow, a USD daily cap, record-before-retry, and 47040 receipts. No core changes, no Rust.

**Tech Stack:** TypeScript, vitest (root runner), `@x402/core` + `@x402/evm` (Coinbase SDK), `viem` (accounts/EIP-712/public client), `@scure/bip32` + `@scure/bip39` (derivation), existing `@fezchat/protocol` relay plumbing via `consent.ts`.

**Spec:** `docs/superpowers/specs/2026-08-30-x402-wallet-design.md` — the plan argues from it; executors read both.

## Global Constraints

- **Allowance model only:** the master mnemonic never leaves CLI/keychain context; agents hold only their derived per-persona keys. No new custody surface.
- **The signer signs ONLY `TransferWithAuthorization`** with `domain.verifyingContract` equal (case-insensitive) to the pinned USDC contract for the configured network. Any other typed data is refused with an error naming what was refused.
- **Offer pinning:** accept only `scheme === "exact"` AND `network === "eip155:84532"` (config `"base-sepolia"`) AND `asset` = pinned USDC. USD = `Number(BigInt(amount)) / 1e6` only after a bounds check (`raw <= 2**53`).
- **Pinned contracts:** base-sepolia `0x036CbD53842c5426634e7929541eC2318f3dCF7e`. Base mainnet ships as a commented constant with the note `verify against Circle's official USDC docs before enabling`.
- **Policy defaults:** `autoApproveUnderUsd.default = 0` (always ask), `dailyCapUsd = 25`, `network = "base-sepolia"`, `rpcUrl` default `https://sepolia.base.org`. Caller-supplied `maxUsd` is REQUIRED on the tool.
- **Record-before-retry:** the tally + log entry (`status: "signed"`) are written BEFORE the paid retry is sent. A post-payment 402 or an ambiguous failure after send is surfaced with "may have settled — do not retry; check receipts" and never auto-repaid.
- **Wire formats come from the SDK** (`@x402/core` http helpers + `@x402/evm` `ExactEvmScheme`), never hand-rolled. If the published packages' names/exports differ from the docs, verify with `npm info` and adapt; hand-roll only the exact scheme as a last resort, against the spec's mechanics section.
- **Receipts:** kind 47040 via the existing `buildReceipt` (`receipt.ts`) — no new kinds. If its `Network` type doesn't admit an EVM network string, widen minimally where the type is defined; the event tags are strings already.
- **Consent:** reuse `buildConsentRequest`/`awaitDecision`/`poolRelay` from `consent.ts` verbatim — approval is ✅ only; the request text names amount (USD), payTo, and url; sign the HELD offer, never a re-fetched one.
- TDD throughout; tests in `packages/fez-wallet/tests/` run via root `bunx vitest run`. Commit per task. **No live-chain calls in tests** (mock transports / in-test HTTP servers only).

```ts
import { HDKey } from "@scure/bip32";
import { mnemonicToSeedSync } from "@scure/bip39";
import { privateKeyToAccount } from "viem/accounts";

export interface EvmPair { addressHex: `0x${string}`; privateKeyHex: `0x${string}` }

/** The money tree's EVM branch: standard BIP44 so mnemonic+index recovers
 *  in any stock wallet. Index is per-persona, persisted in wallet config. */
export function deriveAgentEvm(mnemonic: string, index: number): EvmPair {
  if (!mnemonicValidate(mnemonic)) throw new Error("invalid mnemonic");
  const key = HDKey.fromMasterSeed(mnemonicToSeedSync(mnemonic)).derive(`m/44'/60'/0'/0/${index}`);
  if (!key.privateKey) throw new Error("evm derivation failed");
  const privateKeyHex = (`0x` + Buffer.from(key.privateKey).toString("hex")) as `0x${string}`;
  return { addressHex: privateKeyToAccount(privateKeyHex).address, privateKeyHex };
}
```
