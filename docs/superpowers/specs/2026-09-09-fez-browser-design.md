# fez-browser: anonymous browser tools

Approved scope: make the verified open → read → close Camofox flow an
installable Fez extension. Package `@fezchat/browser`, directory
`packages/fez-browser`. Full interaction and authenticated per-site grants
remain subsequent work; this package does not claim to implement them.

## Behavior

- `browser_open(url)` opens an HTTP(S) page in a fresh, randomly named
  Camofox session owned by this MCP process and returns its tab ID and URL.
- `browser_read(tab_id, offset?)` returns an accessibility snapshot with
  links, identifies the content as untrusted, and supplies a continuation
  offset from Camofox's native snapshot windows (at most 80,000 characters).
- `browser_close(tab_id)` closes a tab belonging to this MCP process.
  Shutdown closes the entire session, including tabs created by popups.
- Unknown/closed tab IDs, credential-bearing URLs, unsupported schemes,
  malformed upstream responses and HTTP errors fail explicitly.
- Serialize calls within one session so close cannot overtake open. Allow
  at most four explicitly opened tabs; bound upstream requests to 55 seconds
  and responses to 2 MiB. Do not retry browser actions automatically.

## Implementation

One package uses the existing `fez.parts.skill`, `gui`, and npm `bin` seams.
It declares `network:*`, `ui`, and `processes`. The owner starts setup in
Settings; a background extension program installs locked Camofox 1.14.0
and downloads the browser. The panel shows status, failures, retry, and a
real launch test. No download occurs when tools are listed or an agent starts.

Blank `CAMOFOX_BASE_URL` starts a private Camofox child on the first valid
open, with an ephemeral loopback port, fresh keys, and temporary profiles.
MCP shutdown and parent death stop the child; normal shutdown removes the
session directory. No manually started service is required after reboot.
An explicit URL retains the external-server path. Remote endpoints require
HTTPS and an access key; REST redirects are refused.

The sole desktop runtime change is generic: extension-owned Node programs
can provision Fez's existing managed Node runtime from both process seams.
Node installation is serialized and background startup does not block the
webview. There are no new protocol kinds or relay changes.

The extension exposes no cookie import, storage export, arbitrary JavaScript
or server administration tools. Session identifiers are generated by the
extension and never accepted from an agent. This is session separation,
not an OS sandbox or complete network isolation: browser-host deployment
must enforce private-network restrictions. Configure upstream persistence
off for anonymous sessions. Do not attach the extension to an existing
persona without choosing that persona with the user.

## Required desktop workflow

User requirement, 2026-09-09: browser setup and use must be possible through
the Fez GUI. Terminal installation and the manual restart command are
temporary development setup, not the finished user workflow.

Reuse the existing extension installation, agent tool picker, and keychain
settings surfaces. The GUI must cover browser setup, attachment to the
chosen agent (currently Quill), and browser readiness/errors with a way to
start or recover it. Normal use after reboot must not require a terminal
command. Browsing requests continue through the existing Fez conversation.

The desktop webview walkthrough passes installation, setup, testing,
attachment to Quill, reload, and a second test. It uses a fixture for native
installation and a local Camofox process fixture. Separate real checks
cover a clean download/install and compiled MCP browsing against The Verge.
The owner subsequently verified a real Quill DM: after restarting the
standing agent, Quill returned the Verge lead article and link. Failed
startup attempts are cleaned up and reset so GUI setup can repair the
same conversation connection. The npm package and desktop catalog have
separate release steps.

## Verification

Exercise real MCP calls against a local HTTP implementation of the observed
Camofox contract in `packages/fez-evals/tests/browser.test.ts`. Cover content,
pagination, session ownership, close/shutdown, upstream errors, response
limits and endpoint validation. Run package build/check, core typecheck,
the full eval gate and a live stdio MCP test against the pinned Camofox
server reading The Verge. Link the package into the local Fez tool catalog.

The earlier standalone probe read the lead headline and URL in five seconds
on macOS arm64 using Camofox 1.14.0 and Camoufox 152.0.4 beta.30. This is
evidence of upstream feasibility, not the extension's acceptance result.
